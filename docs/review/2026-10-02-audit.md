## Root cause of "rejected twice for the same reason" (5.1.2)

The requirement number repeated; the defect did not. Round 2 (Sep 11) was a wrong deep link; round 3
(Sep 24) was the platform refusing the frame. Shopify counts both as "failure to resolve 5.1.2" and
suspends on the second. Why round 3 happened after we had "fixed 5.1.2":

1. **We verified on our own warm store, not on the reviewer's path.** The Sep 13 check ran on
   `busymate-ai-review-test-5`, provisioned days earlier. Reviewers always use a **fresh dev store**,
   open the app within seconds of installing, cycle plans, and **uninstall → reinstall** (App history
   literally reads "Testing multiple apps"). Fresh install + reinstall were never exercised before
   the Sep 13 resubmission, and both paths were broken (publish window, reinstall deadlock).
2. **Resubmitted 8 hours after the fix, on the first green.** No soak, no second store, no
   close-and-reopen check.
3. **The extension was never re-released.** The active app version is still **`busymate-ai-5`
   (Sep 2, commit 0447ff3)**. Every extension-side change since — the `assistant.js` hardening for
   screencast 3 and the `domains/*` webhook subscriptions — exists only in the repo.
4. **The testing instructions in the Partner Dashboard are the Sep 13 text.** Step 2 still says
   "click Save if prompted"; the "stays on only after Save" wording and the Sep 24 fix line were
   written in `docs/review/testing-instructions.md` but never pasted. The support contact in the form
   is a personal Gmail; the screencast link points at `api.busymate.net` (the storage project the
   platform left on 2026-10-02); the demo-store URL is password-protected with no password given.
5. **Home misled the reviewer at the exact moment they act.** The first paint after install happens
   while `afterAuth` is still publishing, so Home showed "Provisioning" with the CTA enabled and never
   re-checked (0.1.14 fixes this; reproduced live on 2026-10-02 at 11:11 UTC).
